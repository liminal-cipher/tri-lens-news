## 1. Auto-research with codex: How I achieved a 232x Faster Kernel

원문: <https://sankalp.bearblog.dev/autoresearch/> (Hacker News)

🌐 Everyone
인공지능이 스스로 코드를 고치고 성능을 시험하는 과정을 수천 번 반복하여 컴퓨터의 계산 속도를 기존보다 200배 이상 끌어올렸습니다. 전문 지식이 깊지 않은 사람도 인공지능과 질의응답을 주고받으며 복잡한 수학 연산 프로그램을 빠르게 개선할 수 있음을 보여줍니다.

💻 Developers
agent가 CLI 피드백 루프를 활용해 kernel(그래픽 처리 장치에서 실행되는 연산 단위) 성능을 정밀 측정하며 연산 구조를 blocked Householder algorithm(행렬을 블록 단위로 분할하여 병렬성을 높이는 기법)으로 바꿉니다. 압도적인 가속을 얻는 대가로 무수한 자동 제출에 따른 클라우드 연산 비용이 지불되며, 적절한 프롬프트 입력이 없으면 수동적 반복만으로 연산 병목을 극복하기 어렵습니다.

🔬 Researchers
연산 속도 증가가 agent의 자동화된 탐색 능력에 의한 것인지 인간이 입력한 알고리즘 프롬프트의 영향인지 변수가 다각도로 격리되지 않았습니다. Muon이나 Shampoo 같은 최적화 기법의 연산 최적화를 위해 모델 내부의 추론 능력과 외부 환경 피드백이 연산 가속에 미치는 기여도를 분리하여 정량화할 필요가 있습니다.

## 2. Claude Code 세션의 가치를 극대화하는 방법

원문: <https://news.hada.io/topic?id=32534> (GeekNews)

🌐 Everyone
인공지능 개발 보조 도구는 대화가 길어지고 주고받은 정보가 많아질수록 같은 작업을 시켜도 요금이 훨씬 많이 나옵니다.
필요 없는 작업 기록을 제때 정리하고 정확한 파일만 지정해 질문하면 비용을 대폭 줄이면서 빠르게 답을 얻을 수 있습니다.

💻 Developers
대화 맥락을 처리하는 prefill(입력 처리 과정)과 답변을 한 토큰씩 생성하는 decode(출력 생성 과정) 중 후자의 GPU 점유율이 높아 출력 토큰 비용이 약 5배 비쌉니다.
대화 이력을 재활용하는 prompt caching의 효율을 높이려면 세션 중간에 설정이나 effort level을 바꾸지 않고, 대량 출력이 발생하는 명령은 subagent로 격리해야 합니다.

🔬 Researchers
prompt caching 유지와 subagent 분리로 절감되는 토큰 비용이 에이전트의 복합적인 문제 해결 성공률에 미치는 부정적 영향을 정량적으로 갈라내지 못했습니다.
에이전트가 자율적으로 context window(맥락 창)를 요약하거나 삭제하면서도 긴 호흡의 추론 정확도를 저하시키지 않는 최적의 프루닝 정책 수립이 과제로 남습니다.

## 3. Alaya-EVOKE: From Linear-Scaling Supervision to Endless World

원문: <https://arxiv.org/abs/2608.13546> (Hugging Face Papers)

🌐 Everyone
가상 공간을 실시간으로 탐색할 때 영상이 중간에 끊기거나 지나온 장소를 잊어버리지 않는 기술이 개발되었습니다. 화면에 보이는 시점의 정보만 골라 저장하고 불러오는 방식으로 메모리 부담을 줄여 끝없이 이어지는 장면을 빠르게 생성합니다.

💻 Developers
camera-indexed world state bank로 관련 시점만 검색해 denoiser context를 일정하게 유지하고, self-forced rollouts 기반의 distribution-matching objective로 학습한 3-step student를 구동합니다. classifier-free guidance(조건부 출력을 조절하는 기법) 없이 작동하여 H200 GPU 기준 1.5초 분량을 2.11초 만에 연산하지만, 길어진 세션에서 프롬프트 변경에 따른 이벤트 조절 응답성을 지속해서 확보해야 하는 대가가 따릅니다.

🔬 Researchers
장기 연산의 안정성이 teacher 모델의 sparse attention 설계 때문인지 아니면 3-step student로 전달된 분포 맞춤 목적함수의 효과인지가 아직 갈라지지 않았습니다. 오차 누적 억제력이 학생 모델의 복원력에서 나오는지 교사의 수평적 지도 한계에서 비롯되는지 규명하려면 두 요인을 분리하는 ablation이 필요합니다.
