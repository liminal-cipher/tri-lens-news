## 1. LLM 메모리를 만들다 우연히 프로그램 분석 엔진이 된 이야기

원문: <https://news.hada.io/topic?id=33015> (GeekNews)

🌐 Everyone
인공지능과 길게 대화하다 보면 이전에 틀렸다고 밝혀진 내용을 잊어버리고 잘못된 전제 위에서 답변을 계속 이어가는 문제가 생깁니다. 대화 기록을 단순히 검색하는 대신 무엇이 참인지 사실 관계를 추적하여 전제가 바뀌면 연관된 결론까지 자동으로 지워주는 방식이 개발되었습니다.

💻 Developers
LLM을 프런트엔드로 활용해 입력을 중간 표현으로 변환하고 Datalog(선언적 논리 프로그래밍 언어) 기반 엔진인 Lemmalog로 dependency(의존성)와 fixed point(고정점)를 추적합니다. 질문마다 입력하는 문맥 토큰을 획기적으로 줄여 대화가 길어져도 비용 증가를 막아주지만, 초기 extraction(추출) 단계에서 추가 호출 비용이 발생하는 대가를 지불해야 합니다.

🔬 Researchers
자연어 속의 조건부 지식을 튜플 형태의 단순 사실로 변환하는 과정에서 미묘한 맥락이 손실되어 추론 성능이 떨어지는 한계가 남아있습니다. 대화 memory 벤치마크를 넘어 실제 보안 분석 agent(자율형 인공지능 시스템) 환경에서도 가설 폐기와 hallucination(환각) 억제 효과가 유효하게 유지되는지 정밀한 검증이 요구됩니다.

## 3. WarpSAC: Towards the Pinnacle of Scalable Off-policy RL by Rethinking Exploration and Exploitation

원문: <https://arxiv.org/abs/2608.24479> (Hugging Face Papers)

🌐 Everyone
가상공간에서 로봇이 수천 번씩 동시에 연습할 수 있게 되었지만 기존의 조심스러운 학습 규칙이 성능을 억제하고 있었습니다. 대량의 연습 데이터가 들어올 때 제약 장치를 해제하는 방식으로 바꾸자 휴머노이드 로봇의 상자 옮기기 성공률이 5배 가까이 뛰고 실제 배치까지 걸리는 시간도 크게 줄었습니다.

💻 Developers
데이터가 풍부한 GPU 병렬 환경에서는 parameter normalization과 clipped double-Q를 제거한 WarpSAC-A 구성을 적용해 연산 오버헤드를 줄이면서 학습 속도를 개선할 수 있습니다. 반면 데이터 수집이 제한된 환경에서는 두 안정화 장치를 다시 활성화하는 WarpSAC-L을 선택해야 하므로 수집 환경 단위 분기 로직이 필요합니다.

🔬 Researchers
대규모 고속 데이터 수집이 single-Q 환경에서 overestimation bias(가치 과대평가 편향)를 안정적으로 제어하는 수학적 한계선이 명확히 밝혀지지 않았습니다. 또한 Sample Weight Decay가 네트워크 용량 한계와 결합할 때 발생하는 표현력 변화를 단순 탐색 효율 향상 효과와 엄밀히 분리해 검증해야 합니다.
