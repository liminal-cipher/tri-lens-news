## 1. Nvidia announces native GPU programming in Rust

원문: <https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/> (Hacker News)

🌐 Everyone
인공지능 소프트웨어의 기초를 이루는 시스템을 멈춤이나 오류가 적은 안전한 언어로 바꾸는 흐름이 핵심 장치인 그래픽 처리 장치 내부 영역까지 확대되었습니다. 데이터 처리 장치를 작동시키는 명령어를 별도의 번역 과정 없이 안전한 언어로 직접 작성할 수 있게 되어 전체 시스템의 안정성이 크게 높아집니다.

💻 Developers
Rust 소스 코드를 PTX(GPU 커널용 중간 연산 언어)로 직접 컴파일하는 CUDA Rust와 cuda-oxide 백엔드가 도입되어 host와 device 코드를 단일 파일에서 구축할 수 있습니다. 다만 nightly toolchain 사용과 빌드 시간 증가라는 대가가 따르므로 추상화 수준이 높은 Tile 모델과 미세 제어가 가능한 SIMT(단일 명령 다중 스레드) 모델 중 최적의 트랙을 선택해야 합니다.

🔬 Researchers
Pliron IR 기반 파이프라인과 LLVM 백엔드가 기존 NVCC(NVIDIA C++ 컴파일러) 수준의 수동 최적화 커널 성능을 온전히 내는지에 관한 실증적 비교가 필요합니다. 다국어 interop(상호 운용성) 지원 시 발생하는 런타임 오버헤드와 하드웨어 아키텍처별 Tile IR 자동 컴파일 최적화의 기여도를 정밀하게 분리해내는 과제가 남아있습니다.

## 2. Training a 4B model to produce 81% faster query plans than Postgres

원문: <https://rohanbansal.com/qorl> (Hacker News)

🌐 Everyone
데이터베이스가 복잡한 정보를 찾아오는 순서를 조율하는 작업은 경우의 수가 너무 많아 기존 시스템도 종종 비효율적인 길을 선택했습니다. 소형 인공지능 모델이 가장 빠른 처리 결과를 내도록 반복해서 훈련시킨 결과 데이터 검색 시간이 절반 가까이 줄어들었습니다.

💻 Developers
Postgres의 query optimizer(데이터 검색 경로 최적화 도구)가 가진 join ordering 문제를 4B open-weights 모델에 SFT와 agentic RL을 적용하여 latency를 낮췄습니다. 실행 노이즈를 제어하기 위해 변형된 GRPO 알고리즘을 구현하고 멀티 컨테이너 기반 측정 환경을 직접 구축해야 하는 개발 오버헤드가 수반됩니다.

🔬 Researchers
성능 향상이 off-policy distillation 단계에서 수집한 agent trajectories의 정교함 덕분인지 RL 과정에서의 탐색 결과인지 명확하게 분리되지 않았습니다. 비균일 데이터 분포를 갖는 복잡한 스키마에서도 sub-optimal query plan(데이터베이스 검색 실행 계획)으로 빠지지 않고 일반화될 수 있는지는 추가 검증이 필요합니다.
