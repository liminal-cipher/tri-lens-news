## 1. PostgreSQL Extensions in Go

원문: <https://jespino.github.io/gopgext/> (Hacker News)

🌐 Everyone
Go 언어만으로 PostgreSQL에 새로운 기능을 넣을 수 있게 되었습니다. 이를 통해 개발자는 복잡한 C 코드를 작성하지 않아도 데이터베이스를 확장해 애플리케이션에 맞춤 로직을 바로 적용할 수 있습니다.

💻 Developers
Go 기반 PostgreSQL extension은 함수에 //gopgext:function 주석을 달면 자동으로 C glue와 설치 스크립트가 생성됩니다. 이 과정에서 표준 라이브러리와 제네릭 등을 그대로 사용할 수 있지만, 빌드 시 TinyGo와 PGXS가 필요하고, 확장 로드 시 메모리 복사와 오류 전파가 제한됩니다.

🔬 Researchers
현재 Go 기반 PostgreSQL extension은 기존 contrib 모듈을 그대로 포팅해 테스트를 통과했지만, 고성능 쿼리 플래너와의 통합 비용이 충분히 측정되지 않았습니다. 또한, 다중 확장 동시 로드 시 메모리 관리와 GC(garbage collection) 오버헤드가 PostgreSQL 내부 메모리와 어떻게 상호 작용하는지에 대한 정량적 분석이 필요합니다.

## 2. UI SDK - AI 에이전트가 UI의 기본 동작을 조합해 컴포넌트를 만드는 라이브러리

원문: <https://news.hada.io/topic?id=37600&utm_source=geeknews&utm_medium=rss&utm_campaign=news> (GeekNews)

🌐 Everyone
AI가 UI 기본 동작을 조합해 맞춤형 컴포넌트를 자동으로 만들 수 있는 라이브러리가 나왔습니다. 이 덕분에 일반 사용자는 복잡한 설정 없이도 팝업, 자동완성 등 다양한 인터페이스를 쉽게 활용할 수 있게 됩니다.

💻 Developers
UI SDK는 50가지 이상의 기본 동작을 모듈식으로 제공하고, 이를 AI 에이전트가 선택·연결해 최종 컴포넌트를 생성합니다. 프레임워크 별 렌더링 지원과 접근성 테스트 도구를 포함하지만, 이를 도입하려면 TypeScript 환경 설정과 Apache-2.0 라이선스 준수가 필요합니다.

🔬 Researchers
UI SDK가 자동으로 조합한 동작들의 실제 접근성 품질이 인간 설계와 동등한 수준인지 검증이 부족합니다. 또한 AI 에이전트가 상태를 직접 변경하는 과정에서 발생할 수 있는 보안 취약점과 성능 오버헤드를 정량화하는 연구가 필요합니다.

## 3. Mind2Act World: A Diagnostic Benchmark for Embodied Mind, Physical Action, and Mind-Action Composition in Robotic Manipulation

원문: <https://arxiv.org/abs/2611.26444> (Hugging Face Papers)

🌐 Everyone
새로운 로봇 테스트가 만들어졌습니다. 이 테스트는 로봇이 상황을 기억하고, 정확히 움직이며, 행동 결과를 다시 판단에 반영하는 능력을 동시에 평가합니다.

💻 Developers
이 테스트를 ‘Mind2Act World’라 명명하고, 30개의 시뮬레이션 조작 작업을 세 단계 난이도와 두 환경(클린·랜덤)으로 구성합니다. 각각의 작업은 ‘Mind’, ‘Act’, ‘Mind2Act’ 세 가지 뷰로 나뉘어 평가되며, 시스템은 추가적인 연산량과 복잡한 피드백 루프를 처리해야 합니다.

🔬 Researchers
현재 대부분의 모델은 개별 ‘Mind’ 혹은 ‘Act’ 능력은 어느 정도 보이지만, 두 능력을 결합한 ‘Mind2Act’ 상황에서는 성공률이 크게 떨어집니다. 지속적인 접촉 유지와 장기적인 상태 추적을 동시에 구현하는 방법이 아직 해결되지 않은 핵심 과제로 남아 있습니다.
