## 1. Foundation Models framework

원문: <https://developer.apple.com/foundation-models-framework/> (Hacker News)

🌐 Everyone
Apple이 만든 Foundation Models 프레임워크 덕분에 스마트폰 앱이 인터넷 없이도 텍스트 요약이나 이미지 인식 같은 AI 기능을 사용할 수 있습니다. 사용자는 개인 정보가 외부에 유출되지 않은 상태로 더 똑똑한 서비스를 경험하게 됩니다.

💻 Developers
Foundation Models API는 Swift로 제공되는 단일 인터페이스로 온디바이스 모델과 Private Cloud Compute 모델을 모두 호출합니다. 온디바이스 사용 시에는 네트워크 비용이 없지만 기기 메모리와 배터리를 소비하고, 클라우드 모델을 선택하면 더 큰 모델을 사용할 수 있지만 호출당 비용이 발생합니다.

🔬 Researchers
두 접근 방식은 온디바이스 모델의 성능 한계와 클라우드 모델의 비용·프라이버시 트레이드오프를 동시에 해결해야 하는 과제로 남아 있습니다. Dynamic Profiles와 Evaluations 프레임워크의 효과를 정량화하려면 다양한 모델·프로파일 조합에 대한 체계적인 벤치마크가 필요합니다.

## 2. Edge0-145B: Frontier AI Capabilities on Your Own Computer

원문: <https://edge0.ai/blog/introducing-edge0-145b-frontier-ai-capabilities-on-your-own-computer> (Hacker News)

🌐 Everyone  
이제 145억 개가 넘는 파라미터를 가진 거대한 AI 모델이 개인용 노트북에서 직접 동작해 코딩 보조와 문제 해결, 간단한 작업 자동화를 수행합니다. 이 모델은 최대 29GB 메모리를 사용하고 초당 80개 이상의 토큰을 생성해, 인터넷 연결 없이도 빠르게 결과를 얻을 수 있습니다.  

💻 Developers  
Edge0-145B는 희소 전문가(sparse expert) 구조와 공유 행렬(share large matrices) 설계를 결합해 전체 145B 파라미터 중 실행 시 약 10B만 메모리에 로드하도록 최적화합니다. 이 설계는 메모리와 대역폭 요구를 크게 낮추지만, 여전히 120W 수준의 전력 소비와 호환 GPU·VRAM 사양을 만족해야 하는 비용이 존재합니다.  

🔬 Researchers  
현재 Edge0-145B의 장기 컨텍스트(128K–256K) 유지와 토큰 생성 속도는 여러 하드웨어에서 균일하지 않아 메모리 관리와 스케줄링 알고리즘의 일반화가 남아 있습니다. 또한 모델이 실제 에이전트 작업에서 클라우드 기반 최첨단 모델과 동등한 품질을 보이는지 판단하기 위해 복합적인 벤치마크와 사용자 데이터 보호를 동시에 고려한 평가 프레임워크가 필요합니다.

## 3. Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents

원문: <https://arxiv.org/abs/2611.14320> (Hugging Face Papers)

🌐 Everyone
LLM 에이전트가 과거 작업을 요약한 교훈을 기억해 두면 새로운 과제를 더 빠르게 해결할 수 있지만, 때때로 잘못된 교훈을 그대로 적용해 원래는 풀 수 있던 문제에서도 실패합니다. 이 문제를 해결하기 위해 제안된 ‘교훈 메모리’는 각 교훈을 원래 수행 기록과 연결시켜 필요할 때 원본을 확인하고 교정을 가능하게 합니다.

💻 Developers
교훈 메모리는 각 교훈을 concise insight 형태로 저장하고, 해당 작업의 성공·실패 요약과 raw trajectory와 링크시킵니다. 이 구조를 실제로 구현한 시스템, WikiTrace는 에이전트가 새 과제를 수행할 때 부족한 정보가 있거나 충돌이 감지되면 링크를 따라가며 세부를 보완하거나 교정을 수행하도록 하며, 그 과정에서 추가 연산 비용과 메모리 사용이 발생합니다.

🔬 Researchers
WikiTrace는 교훈 검증을 가능하게 하지만, 링크를 따라가며 원본 trajectory를 재탐색하는 과정에서 대규모 데이터셋에 대한 저장 효율성과 실시간 검색 속도가 아직 충분히 최적화되지 않았습니다. 또한, 어떤 교훈이 부분적으로만 올바르고 다른 부분은 오류인 경우를 자동으로 구분하는 메커니즘이 부족해, 향후에는 fine-grained provenance과 confidence scoring 도입이 필요합니다.
