## 1. OpenAI Agents API

원문: <https://developers.openai.com/api/docs/guides/agents-api/overview> (Hacker News)

🌐 Everyone
인공지능이 복잡한 일을 맡았을 때 스스로 작업을 나누고 외부 도구를 활용하며 작업 상태를 보존하는 기능이 제공됩니다. 사용자가 일일이 매 단계를 지시하지 않아도 긴 시간 동안 파일을 수정하고 코드를 실행하는 연속 업무를 처리합니다.

💻 Developers
Agents API는 Codex harness 기반으로 session 관리, context compaction, orchestration을 제어해 줍니다. 개발자는 multi-agent 구조와 MCP(Model Context Protocol, 외부 시스템 연동 규격) 연결을 손쉽게 구축하지만, 모델 토큰 비용에 sandbox 인프라 요금이 중첩되는 대가를 치릅니다.

🔬 Researchers
context compaction 동작 중 발생하는 압축 손실이 장기 워크플로우의 실행 신뢰성에 미치는 영향은 명확히 규명되지 않았습니다. multi-agent 환경에서 subagent 간의 자율적 하위 작업 분배와 오류 전파 방지가 실제 인지적 협업 모델인지 단순 래퍼 수준인지 갈라내는 체계적인 검증이 필요합니다.

## 2. Cognition launches new SWE-2 model, Rivaling Fable 5.1 and GPT-Astra

원문: <https://cognition.com/blog/swe-2> (Hacker News)

🌐 Everyone
인공지능 코딩 도구가 프로그램을 수정할 때 전체 디렉터리를 샅샅이 뒤지며 시간을 보내는 습관을 고치고 꼭 필요한 파일만 선별해 고치기 시작합니다.
최고 수준의 완성도를 유지하면서도 작업에 필요한 대기 시간과 계산 비용을 획기적으로 낮추어 저렴하고 빠르게 개발 작업을 맡길 수 있습니다.

💻 Developers
단일 RL(Reinforcement Learning, 강화학습) 과정에서 reasoning-effort levels마다 비용 감점을 부여해 focused exploration 동작을 유도합니다.
NVFP4 양자화로 추론 속도를 끌어올렸으나 Devin 플랫폼 환경으로만 순차 배포되므로 weights 직접 확보나 자체 인프라 유연성은 포기해야 합니다.

🔬 Researchers
2.8T 규모의 Kimi K3 base model 역량과 RL 데이터 삼중화 효과가 분리되지 않아 알고리즘 자체의 순수 성능 향상 폭이 명확하지 않습니다.
더불어 Terminal-Bench 4처럼 복잡도가 높은 환경에서는 점수 낙폭이 커서 긴 호흡의 작업에서 generalization(일반화) 한계가 남아있습니다.

## 3. Show-Harness: Just a VLM Agent Can Play Robots

원문: <https://arxiv.org/abs/2609.10522> (Hugging Face Papers)

🌐 Everyone
글과 그림을 이해하는 인공지능이 별도의 비싼 장비나 복잡한 재학습 없이도 로봇을 조종할 수 있게 되었습니다. 일반 컴퓨터 화면에서 행동을 보여주는 것만으로 로봇에게 새 작업을 가르치는 일도 가능해집니다.

💻 Developers
Vision-Language Model(VLM)이 생성한 semantic action unit을 로봇 제어 신호로 변환하여 Vision-Language-Action(VLA) 모델 없이도 구동을 구현합니다. 로봇 사양별 인터프리터를 개별 구현해야 하며 VLM 추론 지연이 실제 로봇 구동 속도를 제한하는 대가가 따릅니다.

🔬 Researchers
추상화된 semantic action space만으로 정밀한 힘 제어나 연속적인 마찰력이 요구되는 물리 상호작용까지 커버할 수 있는지는 검증되지 않았습니다. 성능 향상이 VLM 자체의 추론 능력 덕분인지 인터프리터의 오차 보정 효과 때문인지를 ablation(구성 요소를 하나씩 제거하며 효과를 분석하는 방법) 연구로 분리해야 합니다.
