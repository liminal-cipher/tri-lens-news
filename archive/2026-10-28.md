## 1. Survival LLM: AI assistant and emergency library that runs on your own computer

원문: <https://www.brangus.io/survival-llm> (Hacker News)

🌐 Everyone
Survival LLM은 인터넷이 끊겨도 컴퓨터 안에서 질문에 답해 주는 무료 AI 도우미입니다. 전기·식량·응급처치 같은 상황별 정보를 신뢰할 수 있는 출처와 함께 바로 보여 주어, 비상 시에도 스스로 판단할 수 있게 돕습니다.

💻 Developers
Survival LLM은 사용자의 메모리 용량을 검사해 적합한 로컬 LLM(Nemotron 3.5, Qwen 3.8 등)을 자동으로 다운로드하고, 별도 API 없이 온‑디바이스에서 추론합니다. 큰 모델일수록 정확도가 높지만 5 GB 이상의 디스크와 수십 기가바이트의 모델 파일이 필요하며, 처리 시 CPU·GPU 부하가 증가해 배터리 소모가 빠르게 진행됩니다.

🔬 Researchers
Survival LLM의 현재 구현은 제한된 테스트 시나리오(전력·응급 22문제)에서만 성능을 검증했으며, 실제 재난 상황에서의 사용성을 평가하려면 다양한 언어·문화·인프라 환경을 포함한 대규모 필드 실험이 필요합니다. 또한 모델 크기에 따라 발생하는 허위 정보와 라이선스 충돌 문제를 자동으로 탐지·완화하는 메커니즘이 부재해, 향후 연구에서는 출처 기반 신뢰도 평가와 지속 가능한 업데이트 체계 구축이 과제로 남아 있습니다.

## 2. Cursor Agent SDK - 팀 맞춤형 AI 에이전트를 코드로 만들고 배포하는 프레임워크

원문: <https://news.hada.io/topic?id=36138> (GeekNews)

🌐 Everyone
팀은 이제 자체 지침과 도구, Slack·GitHub 같은 작업 환경에 맞춰 AI 도우미를 손쉽게 만들 수 있습니다. 이 도우미는 코드 검토, 이슈 분류, 정책 확인 같은 반복 업무를 자동화해 사람들은 보다 높은 수준의 작업에 집중할 수 있게 합니다.

💻 Developers
Agent SDK는 지침을 Markdown으로, 도구를 TypeScript 함수로 정의하고, 이를 하나의 프로젝트로 버전 관리하여 팀 내 코드 리뷰와 CI 파이프라인에 통합할 수 있게 합니다. 이 프레임워크는 Slack, PR, 이슈 트래커 등 다양한 채널과 연결하고, 로컬 플레이그라운드와 자동 평가(Evals)를 통해 동작을 검증한 뒤 Cursor 호스팅 또는 자체 Node/컨테이너 환경에 배포할 수 있습니다.

🔬 Researchers
Agent SDK와 Evals를 활용해도 복잡한 의사결정 로직의 신뢰성을 정량화하거나, 하위 에이전트 간 협업 전략을 최적화하는 방법은 아직 충분히 규명되지 않았습니다. 특히 모델 판단과 도구 호출 사이의 경계 설정, 외부 API 호출의 안전성 보장, 그리고 대규모 배포 시 비용 효율성을 평가하기 위한 체계적인 메트릭이 필요합니다.

## 3. DynaFlow: Learning Free-Form Multi-Agent Orchestration

원문: <https://arxiv.org/abs/2610.34467> (Hugging Face Papers)

🌐 Everyone
DynaFlow는 하나의 인공지능이 스스로 언제 다른 인공지능의 도움을 받아야 할지 판단하고, 간단한 스크립트를 만들어 그들을 지시함으로써 수학 문제 풀이 같은 작업의 정확도를 높입니다. 이렇게 사전에 정해진 협업 구조에 얽매이지 않으니, 다양한 질문에 유연하게 대응할 수 있게 됩니다.

💻 Developers
Dynamic coordination은 메인 에이전트가 실행 가능한 workflow 프로그램을 생성하고, 순차·병렬 실행과 verification 과정을 통해 서브 에이전트들을 조율하는 방식입니다. 메인 에이전트만 supervised fine‑tuning으로 학습하고 서브 에이전트는 고정시키므로, 오케스트레이션 학습에 추가적인 compute 비용이 발생하지만 기존 모델을 그대로 활용할 수 있는 대가가 있습니다.

🔬 Researchers
Dynamic coordination과 DynaFlow가 보여준 정보 흐름 강화가 성능 향상에 크게 기여했음에도, 복잡한 다단계 작업에서 verification 오류가 여전히 발생하는 상황이 남아 있습니다. 이러한 오류를 체계적으로 분석하고, 서브 에이전트의 독립적 학습과 오케스트레이션을 동시에 최적화하는 방법을 찾는 것이 다음 연구 과제로 남아 있습니다.
